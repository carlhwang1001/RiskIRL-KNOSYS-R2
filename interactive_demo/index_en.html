EM Dispatch Lab

Ten dispatchers each make 15 dispatch decisions, and the records do not say who made which decision. In every iteration, the current shared reward θ is used to fill in a table of posterior weights over candidate β for each trajectory (E-step), and the whole table is then used to correct θ (M-step). Each card below corresponds to one computational step of the method; every number is computed live in your browser.

Situations A, B and C differ in whether the cheapest engineer is skilled enough for the job. Two actions: C = send the lowest-cost engineer (cheap, may need rework); S = send a skilled engineer (more expensive, fixes the fault first time with probability 0.95). The reward of each step is R = θ₁ × dispatch cost + θ₂ × rework (rework is 1 or 0).

Data: ten identity-unlabeled trajectoriesτ₁ … τ₁₀

Each cell is one dispatch decision: the letter is the situation and the colour is the choice. Click a cell to flip that choice; click a row label to select a trajectory, and the detailed tables below follow it. Changing the data or any parameter returns to iteration 0.

Value of each actionmean-variance Q

Q_β(s,a) = E[R] − ½(β − 1)·Var[R]/R₀ + γ·E[V(s′)]　　R₀ = 1
E[R] = θᵀφ(s,a) = θ₁·cost + θ₂·(1 − fix rate), φ(s,a) = (cost, 1 − fix rate)　　Var[R] = θ₂²·fix rate·(1 − fix rate)

φ(s,a) is the expected feature vector of the dispatch (cost and rework probability), so E[R] is the inner product of θ and φ, the same formula as r̂ = θ̂ᵀφ in Phase B. The variance penalty applies only to the reward of the current step (immediate risk); the continuation value γE[V(s′)] is not penalised. Pick a candidate β to see its Q table. γE[V(s′)] is the same for both actions (the next situation does not depend on the current choice), so the choice depends only on the difference ΔQ = Q(S) − Q(C).

Choice probabilitysoftmax choice model

π(S | s) = exp(λQ(s,S)) / [exp(λQ(s,C)) + exp(λQ(s,S))] = 1 / (1 + exp(−λ·ΔQ(s)))

Each curve is one situation: the vertical axis is the probability π(S | s) of choosing skill first in that situation, the horizontal axis is the candidate β, and the vertical line marks the node selected above. In situations A and B, skill first has the smaller variance, so a larger β favours it; in situation C both actions have the same variance, so β does not affect the choice and only cost matters. How steep the curves are depends on the current θ: they are almost flat at iteration 0 and become pronounced after convergence.

Likelihood of each trajectory under each candidate βtrajectory likelihood

log P(τᵢ | θ, β) = Σₜ log π(aₜ | sₜ)　(transition probabilities do not depend on θ and are omitted)

Step-by-step sum for the selected trajectory and the selected β. Because only the counts of C and S choices in each situation matter, it can also be written as Σₛ [count of S × log π(S|s) + count of C × log π(C|s)].

Overall fitELBO

ELBO = Σᵢ log Σₙ pₙ · P(τᵢ | θ, β⁽ⁿ⁾)　(once the E-step sets q to the posterior table below, the bound equals the marginal likelihood on the grid)

Higher is better. With mean aggregation and a moderate step size it should rise at every iteration.

Posterior tableE-step: posterior wᵢₙ

wᵢₙ = pₙ · P(τᵢ | β⁽ⁿ⁾, θ) / Σₘ pₘ · P(τᵢ | β⁽ᵐ⁾, θ)

The first row is the prior pₙ: the belief in each candidate β before any data are seen, taken from LogNormal(0, 0.75²) and normalised; it is shared by all trajectories and does not change during EM. Every other row is the posterior wᵢₙ of one trajectory; each column is a candidate β, darker means more weight, and each row sums to 1. Comparing a row with the first row shows how far the data have moved the belief; at iteration 0, while θ is still small, the rows look almost like the prior. The posterior wᵢₙ is what the M-step actually uses. Hover over a cell to see its value.

Dots show β̂ and bars show ±σ. These two numbers only summarise the posterior table for reporting and for choosing β in Phase B; the M-step does not use them directly.

Each trajectory's suggested correction to θM-step: per-trajectory gradient

gᵢ = Σₙ wᵢₙ · Σₜ λ (1[aₜ = S] − π(S|sₜ)) · ∂ΔQ(sₜ)/∂θ

The general form is ∂Q(chosen) − E_π[∂Q]; with two actions it reduces to (1[chose S] − π(S)) × ∂ΔQ/∂θ, where ∂ΔQ/∂θ = (Δcost, Δrework rate − (β − 1)·θ₂·Δvariance coefficient) and the last term comes from the variance penalty. The tables show the node-by-node detail for the selected trajectory.

Each thin arrow is one trajectory's suggestion gᵢ; the thick arrows are the three aggregated directions. A pair of suggestions with a negative inner product counts as one conflict. On this page PCGrad uses a fixed pair order and CAGrad uses c = 0.5.

Classroom questionsQ&A

Questions that students actually asked in class. Unless stated otherwise, the numbers use the default setting: example data (seed 12), 64 nodes, initial θ = (−0.5, −0.5), λ = 3, γ = 0.9, iteration 0, and the slider at node 41, β = 1.034. After convergence θ̂ ≈ (−2.209, −3.287).

Q1In the “Value of each action” table, where do the displayed candidate β, E[R], Var[R] and γE[V(s′)] come from, and how are they computed?

β is the node selected by the “Candidate β on display” slider in that card; the other three numbers follow from θ and the situation table. Take situation A:

Situation Aφ(s,a)E[R] = θ₁·cost + θ₂·(1 − fix rate)Var[R] = θ₂²·p(1 − p)−½(β − 1)Var
Lowest cost(0.20, 0.55)−0.100 − 0.275 = −0.3750.25 × 0.45 × 0.55 = 0.0619−0.0011
Skill first(0.55, 0.05)−0.275 − 0.025 = −0.3000.25 × 0.95 × 0.05 = 0.0119−0.0002

γE[V(s′)]: the next job is A, B or C with probability 0.3, 0.4, 0.3, regardless of the current choice. In each situation take the action with the larger “E[R] − ½(β − 1)Var”, which gives A −0.3002, B −0.2502, C −0.1002 and a weighted mean M = −0.2202; then γE[V] = γM / (1 − γ) = 0.9 × (−0.2202) / 0.1 = −1.982. Because γE[V] is the same for both actions, it cancels in the comparison.

Q2Is β chosen at random at the start?

No. The slider only chooses which node is displayed; by default it sits at node 41, β = 1.034 (node 5, β = 1.58, in the 7-node version), and it does not affect the computation. Every E-step evaluates all 64 candidate β and produces the whole posterior table, so no β has to be chosen in advance.

In the paper the only random element is the initial θ (multiple starts, then selection by ELBO). On this page the initial θ is set by the sliders in the Setup card, (−0.5, −0.5) by default.

Q3E[R] = θ₁ × cost + θ₂ × (1 − fix rate) does not look like θ̂ᵀφ(s,a). Is it the same thing?

Yes. φ(s,a) = (cost, 1 − fix rate) is the expected feature vector of the dispatch, and θᵀφ = θ₁φ₁ + θ₂φ₂ expands to exactly that expression. The table in the “Value of each action” card shows φ(s,a) in its own column.

Phase B simply replaces θ with the converged θ̂: r̂(A, C) = −2.209 × 0.20 + (−3.287) × 0.55 = −2.250; r̂(A, S) = −2.209 × 0.55 + (−3.287) × 0.05 = −1.379.

Note also that there are 64 Q tables, one for each candidate β⁽ⁿ⁾, not one for β̂. β̂ is a posterior summary computed afterwards.

Q4The choice-probability card says that more cautious dispatchers (larger β) prefer skill first in situations A and B. That statement is about π(S | s) in one situation at a time, not about every situation, right?

Right. Each curve is one situation, and the statement holds situation by situation; situation C is the counterexample. The difference between the two actions is

ΔQ(s) = θ₁·Δcost + θ₂·Δrework rate − ½(β − 1)·θ₂²·Δvar,　Δvar = p(1 − p) of S − p(1 − p) of C

β appears only in the last term, and its direction is set by Δvar:

Situationp(1 − p) of Sp(1 − p) of CΔvarAs β grows
A0.04750.2475−0.200stronger preference for skill first
B0.04750.2100−0.163same, smaller effect
C0.04750.04750no change; the curve is flat

The general statement is: a larger β favours, in every situation, the action with the smaller variance in that situation. In this example skill first happens to be the lower-variance action in both A and B; in real dispatching the answer may differ from situation to situation. Situations in which both actions have the same variance carry no information about β.

Q6In the trajectory-likelihood detail, how is step 1 (“A, skill first, π(chosen) 0.557, log π −0.586”) computed?
  1. E[R]: C −0.375, S −0.300 (see Q1).
  2. Penalty: ½(β − 1) = ½ × 0.0343 = 0.01717; C 0.01717 × 0.061875 = 0.001062, S 0.01717 × 0.011875 = 0.000204.
  3. Q: C −0.375 − 0.001062 − 1.98183 = −2.35790; S −0.300 − 0.000204 − 1.98183 = −2.28204.
  4. Choice probability: ΔQ = −2.28204 − (−2.35790) = 0.07586; λΔQ = 0.22758; π(S | A) = 1 / (1 + e^(−0.22758)) = 1 / 1.79648 = 0.557.
  5. Natural log: ln 0.557 = −0.586. Because this is step 1, the running total is also −0.586; adding log π of every subsequent step up to step 15 gives log P(τ | β).

Had the dispatcher chosen lowest cost in this step, π(chosen) = 0.443 and log π = −0.813. Logs are used because the product of 15 probabilities falls below 10⁻⁴; sums are easier to read and numerically safer. Choosing another β changes the penalty, and the whole row changes with it.

Q7What is pₙ in the ELBO formula?

pₙ is the prior probability of the n-th candidate β: the probability, before any trajectory is seen, that a dispatcher's risk attitude falls on node n. The paper uses β ~ LogNormal(0, 0.75²):

pₙ ∝ exp(−½ · (ln β⁽ⁿ⁾ / 0.75)²), normalised so that Σₙ pₙ = 1

For node 41, β = 1.034: ln 1.034 = 0.0337, the raw score is exp(−0.0010) ≈ 0.999, and after normalisation p₄₁ = 0.0525, the largest of the 64 nodes. Node 1 (β = 0.02) has only 6×10⁻⁸ and node 64 (β = 10) has 0.0005; β between 0.5 and 2 carries about 64% in total. The nodes are evenly spaced in ln β, so the 1/β factor of the log-normal density is not needed.

Σₙ pₙ · P(τᵢ | θ, β⁽ⁿ⁾) is the prior-weighted average likelihood, i.e. the grid approximation of the integral over β, called the marginal likelihood P(τᵢ | θ). The first row of the posterior heat map is pₙ.

Q8Can the denominator of the posterior formula, Σₘ pₘ · P(τᵢ | β⁽ᵐ⁾, θ), be written as Σₙ pₙ · P(τᵢ | θ, β⁽ⁿ⁾)?

Numerically, yes: m is a dummy summation index, and any letter sums over nodes 1 to K; the order of the conditioning arguments in P(τᵢ | β⁽ⁿ⁾, θ) and P(τᵢ | θ, β⁽ⁿ⁾) does not change the meaning either.

It is still better not to write it that way. In the numerator, n is “the node being computed”; if the denominator also used n as its summation index, the same symbol would carry two meanings. That is why the paper uses m in the denominator. The denominator is simply the marginal likelihood P(τᵢ | θ), so the formula reads

wᵢₙ = pₙ · P(τᵢ | β⁽ⁿ⁾, θ) / P(τᵢ | θ)　(posterior ∝ prior × likelihood)

Check (7-node version, τ₁, iteration 0, node 4, β = 1): numerator 0.252 × 2.652×10⁻⁵ = 6.683×10⁻⁶; denominator (sum of the seven numerators) 2.578×10⁻⁵; w₁,₄ = 0.259; ln(denominator) = −10.566, which is exactly τ₁'s term in the ELBO. At iteration 0, w₁ₙ (0.051, 0.131, 0.223, 0.259, 0.202, 0.103, 0.032) is close to the prior (0.046, 0.119, 0.208, 0.252, 0.209, 0.119, 0.046), because the likelihoods under different β differ only slightly and the data have barely moved the belief.

Q9Are the situations A, B, C feedback from the environment, or labels attached to the trajectories in advance?

Neither. They are the state sₜ: what the dispatcher can see before deciding, i.e. the s in Q, in the choice probability and in the trajectory likelihood.

  • Not feedback. Feedback is an outcome known only after the decision, such as whether the fault was fixed first time and what it cost. The data on this page have only two columns, situation and choice, with no outcome column; inverse reinforcement learning looks at choices, not rewards.
  • Not a label on a person or a trajectory. It says nothing about whether the dispatcher is cautious; β still has to be inferred from the choices. Nor is it anyone's subjective rating.
  • Where it comes from: it is produced by the environment and then classified by a fixed rule. In this simulation the next situation is drawn by the environment as A, B, C with probability 0.3, 0.4, 0.3, independently of the current choice; this is the transition probability P(sₜ₊₁ | sₜ, aₜ) in the trajectory likelihood. In a real project, the MES records the machine and engineer status at dispatch time, and the record is classified by rules agreed in advance with senior dispatchers, for example “skill gap of the cheapest engineer × whether reassigning costs notably more” (the situation function in the example program mes_sim.py, six classes).

In short, the classification rule is fixed in advance, and the value of the situation is computed at every step from the current state. Real MES records usually also contain an outcome column (for example, fixed: whether the fault was fixed first time); it can be used to estimate environment parameters such as fix rates and costs, but it is not used directly as a reward to train θ.

Q10Methodologically, can the algorithm use the current raw state instead of a situation classification?

Yes, depending on how large the raw state is. The method itself does not require a classification; classifying is a simplification that makes tabular computation possible. Any state s works as long as the following three quantities can be computed:

  1. The expected features and their covariance for every (s, a): the mean-variance Q needs E[R] = θᵀφ(s,a) and Var[R] = θᵀΣ(s,a)θ.
  2. The continuation value γE[V(s′)]: this needs the transition probabilities P(s′ | s, a).
  3. One solution of the mean-variance Q per candidate β: 64 solutions per E-step.
CaseApproachCost and limitations
Discrete and not too large (e.g. number of faults × whether each engineer is idle × skill level)Use it directly as s; the program does not change, only the tables grow. The Bellman operator is a contraction on any finite state space.Each (s, a) needs enough records; in the example program, cells with fewer than 5 records fall back to the overall mean of the same action.
Very large or continuousRepresent Q_β(s, a; θ) with function approximation and solve it by approximate value iteration.In the dispatch simulation, the positions of 20 engineers alone give 13²⁰ ≈ 10²² combinations. The paper's convergence theorem assumes that Q and the gradients are computed exactly; the effect of approximation error is not covered by the paper and has not been tested.
Compromise (most common in practice)Put the actual cost of each record directly into φ, and use a coarser classification only for the state that determines γE[V(s′)].One must still check that the classification does not drop information that dispatchers really use.
  • Too coarse, and information loss is mistaken for risk attitude. Differences within a class that the model cannot see partly inflate Σ(s,a) and hence Var[R], and partly appear as different choices in the same situation; both can be explained away as differences in β.
  • Too fine, and the estimates become unstable. With too few records per cell, fix rates and transition probabilities are poorly estimated, and θ and β become unstable as well.
  • β is identified only from certain states. Only states in which the two actions differ in variance carry information about β (Q4), so the classification should keep the variables that affect outcome variance.

Suggested practice: first run Phase A and Phase B with a situation classification; then add, one by one, the variables that dispatchers actually look at; whenever the state definition changes, compare held-out log-likelihood (holding out some shifts from training), and switch to the finer version only if it predicts better.

This page is an interactive companion to the paper by Kao-Shing Hwang and Jin-Ling Lin on risk-sensitive inverse reinforcement learning from identity-unlabeled demonstrations (under review). The model is a teaching-scale version with three situations, two actions and two features; the computations follow the paper's method, except that the M-step derivative is written in closed form here (the paper's implementation uses central finite differences). It is a teaching illustration, not the code that reproduces the paper's experiments.
